# STATUS — teremok

Обновлено: 2026-10-14

## Что это

Учёт телеком-стройки на **teremok.live** (старая доска объявлений снесена).
Спека — `spec/crm.md`, дизайн-бриф — `spec/design-brief.md`, макет —
Claude Design «Teremok» (реализован целиком). Код в корне репозитория
`raccoontower/teremok`, Vercel деплоит `main` сам.

## Работает (проверено локально в браузере на 390×844 и 1280)

- **Вход** — пароль на роль (`APP_PASSWORD`, `_PARTNER`, `_GC`), cookie на 30 дней, `proxy.ts`. Партнёр смотрит и добавляет расходы (плательщик — он сам), GC видит только свои возмещаемые.
- **Кто платил** — в каждой записи «paid by …», меняется в окне правки.
- **Home** — прибыль месяца = доход − своё − зарплаты; отдельно «Reimbursable
  outstanding» (все чеки, которые GC ещё не вернул). Переключатель месяца.
- **Add** — снимок ИЛИ картинка из галереи ИЛИ без фото вовсе → сумма
  руками → Save. Чтения чека моделью больше нет (21.09.2026): оно угадывало
  сумму не всегда, а перебить неверную цифру дольше, чем набрать свою.
  Вид расхода переключается тапом, объект подставляется из расписания на
  сегодня. Чек — в бакет `receipts`, как доказательство для GC.
  `GEMINI_API_KEY` проекту больше не нужен.
- **Sites** — список с прибылью и висящим reimbursable; объект: статус,
  доход от GC, кто работал (дни, заработано), лента, кнопка GC report.
- **Crew** — до 4 человек; day rate / фикс за объект / % от дохода объекта;
  «заработано» считается из расписания, «выплачено» — из `payroll`.
- **Week** — неделя, тап по дню → объект + состав.
- **Partner split** — по месяцу и за всё время; выплаты партнёрам.
- **GC report** — reimbursable по объекту с чеками и заметками; четыре
  способа отдать: **Copy as text** (в письмо или мессенджер), **CSV**
  (в Excel, приложить к счёту), Export PDF (печать), Share link
  (подписанная ссылка без логина на 30 дней, `/share/<token>`);
  «GC paid this back» → снимает с outstanding.
- **Заметка к расходу** — что именно куплено. По выписке видно только
  «Amazon $170», а управляющей компании нужно «25 коннекторов». В ручном
  вводе фото прикладывается отдельно, без распознавания.
- **Экспорт делёжа** — та же пара «текст / CSV» на `/split`.
- Десктоп: сайдбар, главная в две колонки.

## Подключения

- Ключи: `~/projects/env/teremok.env` (Supabase, APP_*, теперь и GEMINI_API_KEY).
- В Vercel должны стоять: `SUPABASE_URL`, `SUPABASE_SECRET_KEY`, `GEMINI_API_KEY`,
  `APP_SECRET`, `APP_PASSWORD` — владелец поставил, редеплой сделан.
- База — только через пулер `aws-0-us-west-2.pooler.supabase.com:6543`;
  миграции `.venv-db/bin/python` + psycopg, файлы `supabase/migrations/`
  (0001 схема, 0002 выплаты + `expenses.reimbursed_on`).
- Локальная проверка: `npx next start -p 3123`, скриншоты — playwright из
  BuildRight-Academy-v2.

## Домен

`teremok.live` **работает** — сайт открывается с телефона, деплой Vercel
живой. С домашней коробки он недоступен, и это особенность сети, а не
приложения: по обычному DNS (порт 53) даже от 1.1.1.1 и 8.8.8.8 приходит
старый `18.204.152.241`, тогда как через DoH — правильный `216.198.79.1`;
плюс TLS с SNI `teremok.live` не отвечает ни на одном IP Vercel, хотя тот
же IP с SNI `buildrightacademy.us` отвечает нормально. То есть по пути
режется конкретно это имя. Проверять прод с коробки нельзя — только с
телефона или по адресу `*.vercel.app`.

## 2026-10-14 — первый заход больше не падает «This page couldn't load»

Причина (найдена без логов Vercel, воссоздана локально) — изредка на
холодном старте Supabase отвечает на один из восьми параллельных запросов
`loadAll()` ошибкой шлюза `"JWT issued at future"` вместо данных; это и был
ERROR 1604471647. Не миграция, не ключ, не данные — рассинхрон часов между
edge Supabase и PostgREST, проходит сам за секунду-две. `loadAll()` теперь
повторяет пачку запросов с нарастающей паузой; `app/(app)/error.tsx` и
`app/global-error.tsx` — страховка (сам retry() один раз, кнопка «Обновить»
только при повторном сбое); `instrumentation.ts` печатает ошибки рендера в
консоль (Vercel Runtime Logs) на будущее. Подробности — JOURNAL.
