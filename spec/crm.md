# spec/crm.md — учёт для телеком-стройки

Заменяет старый сайт на `teremok.live` (доска объявлений не прижилась).
Код пушится в `raccoontower/teremok`, Vercel деплоит сам.

## Зачем

Владелец считает вручную: Home Depot, электрику, аренду техники, страховки,
Amazon, билеты, бензин, зарплаты, делёж с партнёром. Прошлая попытка —
Telegram-бот с кнопками — дала 7 записей за всё время: **ручной ввод не
приживается**. Значит система строится вокруг того, чтобы вводить было
быстрее, чем не вводить.

## Главное разделение: возмещаемое и своё

Это сердце учёта, и без него цифры врут.

| | возмещаемое (`reimbursable`) | своё (`own`) |
|---|---|---|
| что | Home Depot, электрика, материалы под объект | Amazon, гостиницы, билеты, бензин, страховки, аренда техники |
| кто платит в итоге | управляющая компания (GC) | мы |
| в прибыль | **не входит** — деньги вернут | входит |
| куда идёт | в отчёт GC с чеками, за возмещением | в P&L и в делёж с партнёром |

Пример владельца: «есть тысяча, потратили 500 в Home Depot — это не расход,
потому что вернут, но это растрата, которую надо показать управляющей
компании в материалах». В системе это `reimbursable` с чеком: не уменьшает
прибыль, но попадает в отчёт GC.

Ошибиться тут дорого в обе стороны: посчитать HD расходом — занизить прибыль
и обидеть партнёра; забыть показать GC — не получить возмещение.

## Делёж с партнёром

Партнёр один. Формула на объект и на период:

```
прибыль = доход от GC − свои расходы − зарплаты бригады
каждому = прибыль / 2
```

Возмещаемое в формуле не участвует. Система показывает по объекту и по
месяцу: доход, своё, зарплаты, прибыль, доля каждого, что уже выплачено.

## Бригада

До четырёх человек. У каждого — способ оплаты, задаётся на объект:

- **дневной рейт** — дни на объекте × ставка (дни берутся из расписания);
- **фикс за объект** — сумма или процент от дохода по объекту.

Зарплата — это `own`-расход объекта, входит в делёж.

## Ввод — несколько способов, по частоте

1. **Фото чека** (Home Depot, электрика — самое частое). Модель вытаскивает
   магазин, сумму, дату, предлагает объект и вид (`reimbursable`); один тап
   «верно». Чек хранится — он нужен для отчёта GC.
2. **Ручная форма** для редкого: Amazon, гостиницы, билеты, страховки. Три
   поля и подстановка объекта по расписанию (кто сегодня где).
3. **Пересылка письма** (позже): чек Amazon или билет на адрес системы.

Правило: любой ввод — не больше десяти секунд с телефона. Иначе повторится
судьба бота.

## Срезы

Два обязательных: **по вышке** и **по месяцу**. Всё остальное — производные:
по категории, по партнёру, по работнику.

## Расписание

Кто на каком объекте в какой день. Даёт три вещи: дни для дневного рейта,
подстановку объекта при вводе расхода, и картину загрузки бригады.

## Отчёт управляющей компании

По объекту за период: список `reimbursable` с датой, магазином, суммой и
чеком; итог. Одна кнопка — PDF или ссылка. Это то, что владелец сейчас
собирает руками.

## Стек

Next.js + Supabase, как BuildRight: владелец его знает, деплой через Vercel
уже привязан к репозиторию. Распознавание чеков — Gemini (ключ есть).
Дизайн — тёмный, в духе сделанного для студии; таблицы и цифры читаемы
с телефона, потому что вводить будут с телефона.

## Модель данных

```
sites       объекты: название, адрес, GC, статус, даты
partners    два партнёра, доля 50/50
workers     бригада: имя, способ оплаты по умолчанию, ставка
expenses    объект, дата, сумма, категория, kind (reimbursable|own),
            магазин, чек (файл), комментарий, кто внёс
payroll     объект, работник, период, тип оплаты, сумма
income      объект, дата, сумма — что заплатил GC
schedule    объект, работник, день
```

## Порядок

1. Модель данных и ввод по фото чека — первый рабочий кусок, день.
2. Ручная форма, объекты, расписание.
3. Делёж и отчёт GC.
4. Аналитика по вышке и месяцу.

## Чего не делаем

- Не переносим старый teremok: доска объявлений сносится целиком.
- Не заводим больше двух видов расходов: `reimbursable` и `own` покрывают
  всё, третий вид размоет главное разделение.
- Не строим «универсальную CRM»: клиентов, сделок и воронок тут нет.
